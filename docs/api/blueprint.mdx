## Extension route prefixes

Blueprint mounts extension route files beneath these prefixes:

| Manifest entry                 | Resulting prefix                           | Middleware                                                                             |
| ------------------------------ | ------------------------------------------ | -------------------------------------------------------------------------------------- |
| `requests.routers.client`      | `/api/client/extensions/{identifier}`      | Client session/key, IP restrictions, 2FA and Client rate limiting.                     |
| `requests.routers.application` | `/api/application/extensions/{identifier}` | Administrator and API middleware; implement resource ACL checks in your request class. |
| `requests.routers.web`         | `/extensions/{identifier}`                 | Web session and CSRF middleware; add route-specific authentication/authorization.      |

These prefixes do not automatically authorize a user for a particular server. Add server binding, access, ownership and permission checks for server-specific endpoints. Installed extensions define their own methods and payloads; consult each extension's reference. The built-in endpoint below returns the egg IDs enabled for an extension; `["-1"]` means all eggs. The optional `id` query parameter defaults to `blueprint`.

Source: [Blueprint route provider](https://github.com/Aquadactyl/aquadactyl/blob/2bfd6ae2a30c8152b34b53c53562773a973ae901/app/Providers/Blueprint/RouteServiceProvider.php). The [development guide](/docs/blueprint/development) explains manifest layout.
