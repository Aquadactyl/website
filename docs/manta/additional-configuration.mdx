Fine-tune your Wings node for security, custom ports, and optimal Docker networking.

## SSL / TLS Certificates [#ssl]

When your Aquadactyl Panel is served over HTTPS, web browsers require Wings to use SSL/TLS to prevent mixed content blocking when connecting to the console websocket (port 8080).

### 1. Generate Certificates with Certbot

Ensure your node's FQDN (e.g. `node1.yourdomain.com`) points to the node's public IP address:

```bash
sudo apt install -y certbot
sudo certbot certonly --standalone -d node1.yourdomain.com
```

### 2. Update Wings Configuration

Open `/etc/pterodactyl/config.yml`:

```yaml title="/etc/pterodactyl/config.yml"
api:
  host: 0.0.0.0
  port: 8080
  ssl:
    enabled: true
    cert: /etc/letsencrypt/live/node1.yourdomain.com/fullchain.pem
    key: /etc/letsencrypt/live/node1.yourdomain.com/privkey.pem
```

Restart Wings to apply the certificate:

```bash
sudo systemctl restart wings
```

## Firewall & Port Rules (UFW) [#ports]

Wings and hosted game servers require specific incoming ports to function:

| Port / Protocol         | Service                 | Description                                        |
| :---------------------- | :---------------------- | :------------------------------------------------- |
| **8080/tcp**            | Daemon API & Websockets | Panel-to-node communication and live console       |
| **2022/tcp**            | Built-in SFTP           | Server file management via SFTP clients            |
| **80/tcp**              | Certbot HTTP-01         | Let's Encrypt certificate issuance & renewals      |
| **25565-25600/tcp+udp** | Game Allocations        | Ports allocated to game servers (adjust as needed) |

Configure UFW:

```bash title="Allow Wings ports in UFW"
sudo ufw allow 8080/tcp
sudo ufw allow 2022/tcp
sudo ufw allow 80/tcp
# Example game port range:
sudo ufw allow 25565:25600/tcp
sudo ufw allow 25565:25600/udp
sudo ufw reload
```

## Docker Daemon Tuning [#docker]

Configure `/etc/docker/daemon.json` for reliable container DNS and logging limits:

```json title="/etc/docker/daemon.json"
{
  "log-driver": "local",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  },
  "dns": ["1.1.1.1", "8.8.8.8"]
}
```

Restart Docker and Wings:

```bash
sudo systemctl restart docker
sudo systemctl restart wings
```

## Manta Docker Options [#manta-docker]

These options live under the `docker` section of `/etc/pterodactyl/config.yml` and are specific to Manta. Restart Manta after changing them.

### Image Pull Policy [#image-pull-policy]

`docker.image_pull_policy` controls when Manta pulls an image before it creates a container. It applies to server containers and to the containers that run server installation scripts.

```yaml title="/etc/pterodactyl/config.yml"
docker:
  image_pull_policy: IfNotPresent
```

| Value          | Behavior                                                                                                                                             |
| :------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Always`       | Pull every time. This is the default. If the pull fails but a local copy exists, Manta logs a warning and carries on with it                         |
| `IfNotPresent` | Pull only when no local image has that exact tag                                                                                                     |
| `Never`        | Never pull. Creating the container fails with an error saying the image is not present locally, so images have to be loaded onto the node beforehand |

Images whose name starts with `~` are local images and are never pulled, whatever the policy is.

<Callout type="info">
  `IfNotPresent` and `Never` are useful on nodes with a slow or metered
  connection, behind a registry mirror, or without internet access. With
  `IfNotPresent`, an image that is referenced by a moving tag such as `latest`
  is not updated until you pull it yourself.
</Callout>

### IPv6 on the Docker Network [#ipv6]

Manta creates a Docker network for servers when it starts. IPv6 is enabled on it by default. To create it without IPv6, for example on a host that has no IPv6 connectivity:

```yaml title="/etc/pterodactyl/config.yml"
docker:
  network:
    interfaces:
      v6:
        enabled: false
```

<Callout type="warn">
  This only applies when the network is created. A network that already exists
  keeps its settings, so remove it first if you want the change to take effect.
  Make sure no servers are using it, then restart Manta so it creates the
  network again.
</Callout>

### Mount Check (macOS) [#mount-check]

`docker.mount_check` (default `true`) makes Manta on macOS check at startup that containers can write to the server data directory. It has no effect on Linux. See [Installing Manta on macOS](/docs/manta/installing-manta-macos#mount-check) for what it reports.
