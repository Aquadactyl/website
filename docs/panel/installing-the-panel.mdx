---
title: Installing the Panel
description: Install an exact Aquadactyl release using Git, with bundled Blueprint and managed services.
---

Aquadactyl v1.0-beta is a prerelease. Verify your workload, addons and backups in
staging before opening access to users. The panel is installed separately from
[Manta](/docs/manta/installing-manta), which runs the game containers.

## Requirements [#requirements]

| Component            | Requirement                                                         |
| -------------------- | ------------------------------------------------------------------- |
| OS for the installer | Ubuntu 22.04/24.04/26.04 LTS or Debian 12/13                        |
| PHP                  | 8.5 recommended; 8.4 supported, matching CLI and FPM                |
| PHP extensions       | bcmath, curl, gd, intl, mbstring, PDO MySQL, posix, redis, XML, zip |
| Build tools          | Composer 2, Node.js 24.22.1+, pnpm 12.15.0                          |
| Services             | Nginx, MariaDB/MySQL, Redis, systemd and cron                       |
| Networking           | A public domain, trusted HTTPS certificate and outbound HTTPS       |

Use a dedicated host. The installer provisions packages and services when
needed. Keep database, Redis and Docker sockets off the public Internet. Ubuntu
LTS support dates are documented by [Ubuntu](https://ubuntu.com/about/release-cycle).

## Fetch the release tools with Git [#installation]

```bash title="Install the reviewed release"
git clone --depth 1 --branch v1.0-beta.3 https://github.com/Aquadactyl/Installer.git /opt/aquadactyl-installer
cd /opt/aquadactyl-installer
sudo bash deploy.sh install v1.0-beta
```

Review `deploy.sh` before running it. It fetches that exact panel tag, installs
locked Composer/pnpm dependencies, generates missing application secrets, runs
migrations and initial seeders, initializes bundled Blueprint, builds frontend
assets, and configures Nginx, the `aquaq` queue worker and minute scheduler.
It refuses an initialized panel: use [Updating](/docs/panel/updating-the-panel).

Ubuntu 22.04 uses the PHP PPA to meet the same PHP 8.4/8.5 requirements. The
installer checks OS compatibility before modifying source or configuration and
does not upgrade your OS. For WSL testing, enable systemd first.

If an earlier installer recovered the checkout and then rejected Ubuntu 22.04,
select installer `v1.0-beta.3` and rerun `install v1.0-beta` without
`--refresh-source`; the recovered source and the private backup are retained.

### An unfinished checkout already exists

If the installer finds unused source from an earlier attempt (for example,
`canary`), select the patched installer and recover that checkout:

```bash
cd /opt/aquadactyl-installer
git fetch origin tag v1.0-beta.3
git checkout --detach v1.0-beta.3
sudo bash deploy.sh install v1.0-beta --refresh-source
```

The installer fetches and validates the release before moving the complete old
directory into a private backup under `/var/backups/aquadactyl/preinstall-*`.
It preserves `.env`, application keys, `.blueprintrc` and `storage/app` uploads.
Initialized panels are refused even with this flag; use the update guide instead.
The installer revision and the panel release are separate versions. Git's
detached-HEAD notice is expected for a release checkout.

### Resume after a database or configuration failure

The installer tests database access before key generation and maintenance.
An existing database account keeps its existing password, even when a previous
attempt wrote a different password to `.env`. Repair the account credentials or
grants first, then resume a matching unfinished installation that already has
dependencies:

```bash
sudo bash deploy.sh install v1.0-beta --resume
```

For a saved local TCP database at `127.0.0.1`, the installer can configure a new
dedicated login before resuming:

```bash
sudo bash deploy.sh repair-database
sudo bash deploy.sh install v1.0-beta --resume
```

The repair privately backs up `.env`, verifies the new account and changes only
the database username and password. The login is limited to the saved panel
database; existing accounts, passwords and data are preserved. It requires local
administrator socket access through `sudo mariadb` and refuses remote databases,
URL/socket overrides and system databases.

Resume reuses `.env`, application keys and uploads, finishes installation and
clears maintenance only after success. It refuses initialized Blueprint/addon
state, which must use the update guide. Do not drop the database or regenerate
`APP_KEY` to fix authentication. `--resume` cannot be combined with source refresh.

Follow the prompts for your HTTPS panel URL, database and initial administrator.
For unattended deployment, configure `.env` in the dedicated `PANEL_ROOT` first
and use `NON_INTERACTIVE=1`. Keep `APP_KEY` and `HASHIDS_SALT` in a secure backup:
changing them can make saved credentials or identifiers unusable.

## Configure HTTPS, email and proxies [#configuration]

Obtain a trusted TLS certificate for the panel hostname before inviting users.
The installer's temporary self-signed certificate only bootstraps Nginx; browser
certificate errors mean HTTPS setup is unfinished. See
[Webserver configuration](/docs/panel/webserver-configuration).

Set `APP_URL` to the public HTTPS origin. Behind Traefik, Dokploy or another
reverse proxy, set `TRUSTED_PROXIES` to the proxy's actual addresses/CIDRs and
forward the original protocol, hostname and port. Keep secure cookies enabled.

Configure SMTP, Mailgun, Postmark or SES under **Admin > Settings > Mail** and
send a test email. Verify password-reset delivery before launching.

## Complete first-run setup [#next-steps]

1. Sign in as the administrator and complete **Admin > Settings > Panel setup**.
2. Set your site name, logo and primary colour.
3. Optionally create a location/node and test authenticated daemon connectivity.
4. Optionally create additional administrators with separate credentials.
5. [Install Manta](/docs/manta/installing-manta) on nodes, configure allocations,
   then install/start an expendable test server and check its console and files.

PWA installation and its offline connection page are configured under
**Settings > PWA**. Server management always needs a live connection.

Blueprint is included: install trusted packages with `blueprint -i myaddon` and
remove them with `blueprint -r myaddon`. Keep every original package for updates.
Optional web installation uses a dedicated privileged worker; follow the
[administration reference](https://github.com/Aquadactyl/aquadactyl/blob/main/docs/ADMIN-OPERATIONS.md).

## Operator-managed installations [#manual-installation]

Operators who already manage PHP, Nginx, queues and deployment automation can
clone the panel source directly:

```bash
git clone --depth 1 --branch v1.0-beta https://github.com/Aquadactyl/aquadactyl.git /var/www/aquadactyl
```

A Git checkout needs locked dependencies, a frontend build, environment/secrets,
migrations and Blueprint initialization before it can serve requests. Follow the
[deployment reference](https://github.com/Aquadactyl/aquadactyl/blob/main/docs/DEPLOYMENT.md)
and templates under `deploy/`. Serve only `public/`, keep code root-owned and
restrict web-writable paths to `storage/` and `bootstrap/cache/`. Add exactly one
queue worker and one minute scheduler. The local Docker stack uses public test
credentials and is intended for development.
