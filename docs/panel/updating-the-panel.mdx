---
title: Updating the Panel
description: Fetch a pinned release through Git, preserve panel data and addons, and recover from a failed update.
---

Update the panel and bundled Blueprint together. v1.2-beta is a prerelease;
validate it against your workload and original addon packages in staging first.
Do not run upstream `blueprint -upgrade` or `git pull` over addon-modified files.

## Before updating [#requirements]

- Back up the database, `.env`, `APP_KEY`, `HASHIDS_SALT`, storage and addons
  off-host, and verify that the backup can be restored.
- Keep every installed `identifier.blueprint` package in the panel root.
- Check PHP 8.4/8.5, Node.js 24.22.1+, Composer 2 and pnpm 12.15.0.
- Schedule a maintenance window. Coordinate all instances if several
  application servers share the database.
- Keep the existing panel directory, credentials and queue service name.

## Fetch the release tools [#automated-update]

If this is your first managed update:

```bash
git clone --depth 1 --branch v1.3-beta https://github.com/Aquadactyl/Installer.git /opt/aquadactyl-installer
```

For an existing tools checkout, review and select the installer tag:

```bash
cd /opt/aquadactyl-installer
git fetch origin tag v1.3-beta
git checkout --detach v1.3-beta
sudo bash deploy.sh update v1.2-beta
```

For a panel at the inherited path, keep it there:

```bash
sudo PANEL_ROOT=/var/www/pterodactyl bash deploy.sh update v1.2-beta
```

The updater fetches the **exact panel Git tag**, rather than the moving `main`
branch. `.installed-commit` records that source commit. It validates source and
addon packages before maintenance, stops active queue/Blueprint workers, creates
private SQL/filesystem backups, removes obsolete core files and installs the new
source while retaining environment, uploads and addon state. It installs locked
dependencies, runs migrations and Blueprint's seeder, reapplies addons, rebuilds
assets/caches and restarts previously active services.

A missing addon package, failed reapplication, migration, build or service restart
stops the deployment. Inspect the error and retained maintenance state before
bringing the panel back online. The updater does not reverse migrations.

Installer v1.3-beta fixes the `Invalid installed extension identifier` error
when Blueprint records contain leading pipe markers. If an older updater stops
at that audit, select the fixed installer and retry; preserve the installed-addon
metadata. See [Blueprint inventory troubleshooting](/docs/panel/troubleshooting#blueprint-inventory).

## Legacy addons that patch core files [#core-addon-scripts]

Panel v1.2-beta stops when an addon lifecycle script fails. Older addons such as
Subdomains may copy backend PHP files and edit core routes. On a root-owned
panel those changes require an explicit operator decision. After reviewing all
installed addons' scripts, allow them for one managed update with:

```bash
sudo BLUEPRINT__ALLOW_CORE_SCRIPTS=1 bash deploy.sh update v1.2-beta
```

This runs addon lifecycle scripts as root and keeps panel source root-owned.
The default command does not enable it. Inspect a failed update's output and
backup before retrying; scripts may already have made partial changes.

After updating, queue a check under **Admin > Settings > Updates** to refresh
daemon product labels and replace older cached release notes. Manta and Wings
checks use separate repositories; beta installations also check prereleases.

## Native PHP-FPM hardening [#native-fpm-hardening]

Aquadactyl v1.2-beta disables PHP session upload progress in its native PHP
template. Updating panel source does not replace the host's active FPM settings.

For an existing Debian/Ubuntu native deployment, apply just this setting without
overwriting custom PHP limits. Set the version to the PHP-FPM service used by
the panel (8.5 below, or 8.4), then validate before reloading:

```bash
PHP_FPM_VERSION=8.5
printf '%s\n' 'session.upload_progress.enabled = Off' | sudo tee "/etc/php/${PHP_FPM_VERSION}/fpm/conf.d/99-aquadactyl-session.ini" >/dev/null &&
sudo "/usr/sbin/php-fpm${PHP_FPM_VERSION}" -t &&
sudo systemctl reload "php${PHP_FPM_VERSION}-fpm"
```

Check the FPM configuration, rather than only the PHP CLI configuration:

```bash
sudo "/usr/sbin/php-fpm${PHP_FPM_VERSION}" -i | grep '^session.upload_progress.enabled'
```

It should report `Off`. Docker already disables this setting. Continue installing
PHP security updates from your package provider.

## Downloaded archives [#manual-update]

Download `panel.tar.gz` and `SHA256SUMS` from the same
[published release](https://github.com/Aquadactyl/aquadactyl/releases/tag/v1.2-beta).
Verify the archive, then pass its reviewed 64-character checksum:

```bash
sudo bash deploy.sh update --archive /path/to/panel.tar.gz YOUR_64_CHARACTER_SHA256
```

Checksums detect download corruption; trust in the release publisher is still
required. The managed update needs the locked Composer/pnpm packages available
through your network or package caches.

## Verify after updating [#verification]

Sign in and check the version under **Admin > Overview**, update notes, settings
saves over HTTPS and email delivery. Check node connectivity, server rows, power,
console/WebSockets, files, schedules and a test backup. Check installed addons.
Server management requires a live daemon connection even when PWA is enabled.

Manta updates are separate: follow [Updating Manta](/docs/manta/installing-manta#updating).

## Recovery [#recovery]

Backups are under `/var/backups/aquadactyl/TIMESTAMP-XXXXXX` by default. The
filesystem snapshot includes application secrets, vendor packages and addon
state. Deployment logs are private unique files under `/var/log`.

1. Keep maintenance active and stop PHP-FPM and the relevant queue/Blueprint
   services. Record the failing deployment and backup paths.
2. Restore the complete filesystem snapshot to the original path and restore
   `database.sql` into the matching database using administrator credentials.
   Restore files and SQL from the same snapshot.
3. Reinstall the restored version's locked packages as needed, repair permissions
   with `deploy.sh permissions`, regenerate caches and restart the original services.
4. Validate the restored panel, then run `php artisan up` as the web user.

See the [deployment reference](https://github.com/Aquadactyl/aquadactyl/blob/main/docs/DEPLOYMENT.md)
for paths and manual service/cache commands. Preserve the application keys
throughout recovery.
