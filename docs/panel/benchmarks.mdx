## Build duration

One discarded production build per panel, then five measured builds each, sequentially in rotating order. Full package-manager production build command, including upstream clean, SDK generation and postbuild checks. Dependencies installed from unmodified lockfiles before timing with install lifecycle scripts disabled. Each sample starts a fresh CLI process; filesystem/dependency caches remain warm. All checkouts reside on the same Linux named volume in one four-CPU, 8 GiB builder. Total assets cover all manifest-emitted JavaScript and CSS routes; they are not dashboard HTTP transfer sizes. Per-file gzip level 6. Dependency installation, PHP image builds and artifact analysis are excluded.

## Environment and reproduction

Intel(R) Core(TM) i7-14700KF, 28 logical host CPUs, Linux/WSL2 Docker. The builder was restricted to four CPU cores and 8 GiB; Node v24.22.3. All three checkouts and dependency trees lived on the same Linux volume. Existing unrelated host services remained running; no CPU pinning or repeated clean-machine trials were performed. This is a warm repeated local build comparison, not dependency-install time or CI wall time.

Use the [repository harness](https://github.com/Aquadactyl/website/tree/main/scripts/benchmark-builds.mjs) with a JSON configuration containing the three clean source roots, exact SHAs, release names, package-manager executable/arguments, lockfile names, asset directories and output directory. Install the locked dependencies before timing and run inside a four-CPU, 8 GiB Linux container. The measured runner download above preserves the exact code used for this run.

[Historical October v1 results](/benchmarks/panels.json) and [October v2 build results](/benchmarks/panel-v2-builds.json) remain available. Their old bundler-only/dashboard-closure measurements use different scopes and must not be mixed with these full-command, all-route figures.
