Start with the symptom you can see, check the matching component, and make one
change at a time. Most checks in these guides inspect the current state; repairs
are explained separately.

If you use someone else's panel, start with the browser checks and collect the
error for your panel administrator. Host commands are for the operator of that
installation.

## First checks [#first-checks]

1. Record the exact error, action and time, including your timezone. Reproduce
   once so you can find the matching log entry.
2. Check the scope: one account, one server, one node, or the whole panel. A
   working panel page does not establish that the browser can reach a node.
3. Check the installed versions against [current releases](/docs/panel). Panel,
   Manta and Installer versions are separate. An installer version argument does
   not update an older checkout of the installer itself.
4. Note what changed immediately before the problem: update, extension, domain,
   proxy, credentials, storage path or service configuration.
5. Follow the matching guide and retry after a specific correction. Keep a backup
   before changing configuration or running an update.

<Callout type="warn">
  Preserve the panel's application key, database, node configuration and server
  volumes. Deleting them, regenerating an existing application key, making files
  world-writable, or bypassing certificate checks can cause data loss or expose
  the installation. They are not general troubleshooting steps.
</Callout>

## Collect useful evidence [#support]

Use a short excerpt around the failure, rather than an entire log directory.
Panel log previews and Manta diagnostics are described in the component guides.
Keep `APP_DEBUG=false` on a public panel, even when temporarily collecting debug
logs.

Review evidence before sharing it. Remove passwords, application keys, node/API
tokens, OAuth client secrets, Discord webhook URLs, session cookies and bearer
credentials. Browser network exports and WebSocket URLs can contain tokens too.
Automatic redaction still needs a human review. Never attach a complete `.env`
or node `config.yml` to a public report.

If the relevant checks do not resolve it, use this template for your administrator
or a report in the [Panel](https://github.com/Aquadactyl/aquadactyl/issues) or
[Manta](https://github.com/Aquadactyl/manta/issues) repository:

```text
Component and installed version:
Deployment: native Linux / Docker / Dokploy / macOS
Host OS and architecture, if relevant:
Scope: one user / one server / one node / all users
Action and exact error or HTTP status:
Time and timezone:
Steps to reproduce:
Expected result and actual result:
Recent changes:
Checks performed and their results:
Relevant, reviewed and redacted log excerpt:
```

Suspected compromise, exposed credentials, or potential data corruption should
be escalated privately. Preserve logs and backups before further changes.
